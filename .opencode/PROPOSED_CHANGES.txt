PROBLEM: probeDurationFromUrl already returns MILLISECONDS — getDurationFromBytes = bytes*8/128 is
bits / (128 bits/ms) at 128kbps (e.g. 4.8MB -> 300,000 ms). The extra *1000 inflates the duration
1000x, breaking buildEstimatedTimeline's verse boundaries (verse tracking never advances) and the
inflated value is cached in audio:duration2, persisting across sessions.

CURRENT CODE:
  const probe = await probeDurationFromUrl(url);
  if (probe > 0) dur = Math.round(probe * 1000);

PROPOSED CODE (drop the double unit conversion):
  const probe = await probeDurationFromUrl(url);
  if (probe > 0) dur = probe;

AUDIT SUMMARY: unit mismatch ms -> us in the fallback-of-fallback path; all other timeline/seek
math is already ms-consistent. Non-breaking: only affects the duration estimate value; timeline
entries, seekToPlayer, and cache keys unchanged.
