TARGET FILE: src/screens/QuranViewScreen.tsx  (line 440)
-----------------------------------------------------------------------------------------------------
PROBLEM: oddPartnerKey is inverted. Pairing from pagePairsFor is [1],[2,3],[4,5]... and SpreadItem
renders the ODD page on the LEFT half and the EVEN (anchor) page on the RIGHT half. For an even
currentPageNum the displayed partner is currentPageNum+1, but the code computes currentPageNum-1
(i.e., the previous pair's odd page). Left-half strokes are therefore saved under the wrong page
key, the left half of the canvas shows the wrong page's drawing, and for an odd currentPageNum
(e.g. via page list/deep link) the current page's paths are shifted +halfOrigin onto the wrong
(right) half. Also contradicts prefetchPartner (correct +1/-1) at line 188.

CURRENT CODE:
  const oddPartnerKey = splitOn ? `page_${currentPageNum % 2 === 0 ? currentPageNum - 1 : currentPageNum + 1}` : null;

PROPOSED CODE (one-line swap of the ternary branches):
  const oddPartnerKey = splitOn ? `page_${currentPageNum % 2 === 0 ? currentPageNum + 1 : currentPageNum - 1}` : null;

AUDIT SUMMARY: sign/parity inversion in split-mode drawing composition; data misattribution to
wrong page keys. Fix is a pure swap; no other call sites depend on the old (wrong) value.
Non-breaking: single-mode drawing unchanged; even-anchor placement/shift signs already correct.

TARGET FILE: src/utils/audioPlayback.ts  (line 160)
-----------------------------------------------------------------------------------------------------
PROBLEM: probeDurationFromUrl already returns MILLISECONDS — getDurationFromBytes = bytes*8/128 is
bits / (128 bits/ms) at 128kbps (e.g. 4.8MB -> 300,000 ms). The extra *1000 inflates the duration
1000x, breaking buildEstimatedTimeline's verse boundaries (verse tracking never advances) and the
inflated value is cached in audio:duration2, persisting across sessions.

CURRENT CODE:
  const probe = await probeDurationFromUrl(url);
  if (probe > 0) dur = Math.round(probe * 1000);

PROPOSED CODE (drop the double unit conversion):
  const probe = await probeDurationFromUrl(url);
  if (probe > 0) dur = probe;

AUDIT SUMMARY: unit mismatch ms -> us in the fallback-of-fallback path; all other timeline/seek
math is already ms-consistent. Non-breaking: only affects the duration estimate value; timeline
entries, seekToPlayer, and cache keys unchanged.
