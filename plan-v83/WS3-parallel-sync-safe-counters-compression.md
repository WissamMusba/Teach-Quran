# WS-3 — Parallel Student Sync + Safe Counters + Compression (src/api/sync.ts, one line in src/database/localDB.ts)

Implementation brief for a READ-ONLY-planned change. Verify every line reference against the current source before editing; line numbers below were verified against the working tree at plan time.

## GOAL

Three approved changes in the sync layer: (a) the pull pass currently processes students strictly one-after-another with many awaited Firestore reads each — bounded concurrency (2–3 students) makes multi-student pulls ~3× faster while keeping one atomic SQLite `savePullBatch` per student; (b) canvas-chunk pushes stamp versions from local counters with NO cloud read, so a stale device can regress cloud versions and directional pulls skip newer data — the bookmark path already solves this with `runTransaction` + `max(local, cloud)+1`, and the canvas push must adopt the same pattern with stale-doc skipping; (c) `pushAllDrawings` uploads raw, uncompacted strokes into 10-page group docs that can exceed Firestore's 1 MB document limit → silent write failure — it must apply the compaction/thinning the active-save path already uses, plus an ~800 KB group-size guard that fails safe. Net user-visible effect: sync is faster, versions never regress, and heavily drawn pages actually reach the cloud instead of silently failing.

### 3b — Transactional, max-clamped canvas-chunk pushes

5. Replace the chunk-slice batch (94–130) with a per-slice `runTransaction` that mirrors the bookmark transaction (143–165):
   - In the transaction, first `tx.get(overviewRef)` (as at 144) and `tx.get` each `draws` doc in the slice (per-doc reads).
   - Per chunk: `cloudV = snap.exists ? (snap.data()?.v || 0) : 0`. **Skip the chunk's write when `cloudV > local.v`** (cloud strictly newer → local is stale; do NOT regress the doc). Also skip `markSynced`-before-commit (see below). When writing, use `v = Math.max(cloudV, local.v) + 1` on the `draws` doc AND record that final v in the slice's manifest `pages` entry.

On transaction failure: `bumpAttempt` all slice keys (as at 128).

## RISKS & WARNINGS

- **Transaction op budget:** 450-chunk slices + per-doc reads blow the 500-op transaction ceiling — the single most likely silent failure of 3b. Enforce the smaller slice constant and count ops. If Firestore returns "too many operations", the wrapper catch (126–129 pattern) will bumpAttempt and retry forever against the same failure — the slice constant is the fix, not retries.
- **Transaction retry loops:** `runTransaction` auto-retries on contention; the bookmark path already relies on this (143–165). Keep default retry behavior; do not add your own retry loop inside the transaction callback (nested transactions are illegal). Contention with 3a's concurrent pulls is possible — busy_timeout covers the SQLite side, Firestore transactions self-throttle.
- **busy_timeout scope:** it only helps the SQLite connection AFTER it is set — it must live in `initDatabase` (12–71), NOT on a per-query statement. WAL (16) + busy_timeout (new) + synchronous=NORMAL (17) are the documented safe trio; do not change journal mode.
- **norm double-scale:** the double-scale trap is real (documented at 429–431). Two rules: (1) appended strokes get `norm: 1` + compacted points in the SAME expression; (2) cloud-owned strokes are copied through untouched (456). Never re-compact a stroke that already carries `norm`.
- **Geometry mismatch (accepted):** `pushAllDrawings` runs outside the reader, so compaction uses the last active-save geometry or window fallback. On rare rotation/resize boundaries the fractions can differ slightly from the drawing device's canvas; `pullDrawings` denormalizes for the receiver, so strokes still land at the correct WORD, not necessarily the exact pixel — same tolerance `pushDrawings` already ships with (392/497).
- **Oversized ranges stay skipped** until drawn-over/shrunk: the fail-safe guard holds local data indefinitely rather than corrupting the cloud doc. Document in the comment; do NOT "fix" by writing anyway (that reintroduces the silent 1 MB failure).
- **Version conventions:** after 3b, the chunk push no longer writes `v: local.v` verbatim (103–108). Any debugging/export tool that assumed that mapping must be told: `draws` docs can carry `max+1` and stale-skip means some dirty rows resolve to "cloud newer" — `markSynced` for those is INTENTIONAL (content is not lost; pull converges). Do not leave such rows dirty forever by accident: the skip branch MUST still clear the queue row (via the manifest-convergence + markSynced described in change 5).
- **Manifest interplay:** 3b changes the version bookkeeping the pull side diffs against (275, 296, 226). Because every written version is now `> cloud` and every skipped one equals `cloud`, the directional-pull axioms (`local.v >= cloudV` → skip) remain sound.
